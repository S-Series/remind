# Game Overview

> 문서 상태: Draft 0.1  
> 최종 갱신: 2026-07-21  
> 목적: 프로젝트가 무엇을 만들고 있으며, 현재 데모가 어디까지 구현해야 하는지 짧게 고정한다.

## 1. 한 줄 설명

**ReMind는 10개 키와 10개 레인을 사용하는 키보드 리듬 게임으로, 프레임 상태가 아니라 실제 입력 시각과 오디오 시각을 기준으로 정교하고 신뢰할 수 있는 판정을 제공하는 것을 핵심 목표로 한다.**

## 2. 프로젝트 목표

### 확정

- 10레인 키보드 리듬 게임의 플레이 가능한 데모를 만든다.
- 오디오, 입력, 채보가 같은 시간축에서 동작하도록 구성한다.
- 프레임 드롭이 발생해도 판정 결과가 입력 이벤트 시각을 기준으로 유지되게 한다.
- 별도 에디터에서 만든 채보를 게임이 안정적으로 불러올 수 있게 한다.
- 판정 규칙을 코드보다 먼저 문서와 자동 테스트로 고정한다.

### 임시

- 첫 데모는 PC 키보드만 지원한다.
- 첫 데모의 노트 종류는 Tap과 Hold로 제한한다.
- 온라인 기능, 계정, 랭킹은 첫 데모 범위에서 제외한다.

### 미정

- 최종 게임 모드와 진행 구조
- 수록곡 제공 방식
- 난이도 체계와 등급 명칭
- 최종 점수 공식
- 아트 콘셉트와 세계관
- 상용 배포 범위

## 3. 핵심 재미

### 3.1 판정을 신뢰할 수 있는 플레이

플레이어가 실패했을 때 게임의 프레임이나 오디오 지연이 아니라 자신의 입력 차이를 이해할 수 있어야 한다.

필수 요소:

- 판정 결과의 일관성
- Early/Late 표시
- 사용자 입력 오프셋 보정
- 프레임 드롭과 화면 연출로부터 분리된 판정

### 3.2 10키 동시 입력의 손맛

10개 레인을 사용하는 만큼 단일 키 연타보다 양손 배치, 코드 입력, 좌우 이동과 패턴 해석이 핵심이 된다.

필수 요소:

- 서로 독립적인 10개 레인
- 같은 시각의 다중 입력 처리
- 키를 누른 상태와 새 입력의 명확한 구분
- 키보드 고스팅을 확인할 수 있는 입력 테스트

### 3.3 채보와 플레이 결과의 예측 가능성

에디터에서 배치한 시각이 게임에서 같은 결과로 재생되어야 한다.

필수 요소:

- 버전이 명시된 채보 포맷
- 정수 밀리초 기반 노트 시각
- 에디터와 런타임이 공유하는 유효성 검사 규칙
- 채보 오프셋과 사용자 오프셋의 분리

## 4. 기본 플레이 흐름

```text
게임 실행
  -> 곡 선택
  -> 난이도 선택
  -> 필요 시 오프셋 확인
  -> 카운트다운
  -> 플레이
  -> 일시정지 / 재시작 가능
  -> 결과 화면
  -> 재도전 또는 곡 선택 복귀
```

첫 데모에서는 곡 선택 화면을 단순 목록으로 구현해도 된다.

## 6. 성공 기준

데모의 성공은 콘텐츠 양보다 아래 항목으로 판단한다.

1. 같은 입력 기록을 재생했을 때 같은 판정 결과가 나온다.
2. 200ms 수준의 의도적인 메인 스레드 정지에서도 이벤트 시각 기준 판정이 유지된다.
3. 에디터에서 저장한 채보가 별도 수작업 변환 없이 로드된다.
4. 오프셋의 부호와 역할을 개발자와 플레이어가 혼동하지 않는다.
5. 일시정지, 포커스 이탈, 재시작 이후 이전 입력이 남지 않는다.
6. 판정 경계값이 자동 테스트로 검증된다.

## 7. 설계 원칙

- 판정 데이터와 화면 표시를 분리한다.
- 노트 GameObject가 없어도 판정할 수 있어야 한다.
- `Time.deltaTime` 누적으로 곡 시간을 만들지 않는다.
- 한 노트마다 독립적인 무거운 `Update()`를 두지 않는다.
- 채보 데이터는 로드 후 가능한 한 불변으로 취급한다.
- 시스템 사이에는 명시적인 데이터 흐름을 둔다.
- 임시 결정은 코드에만 숨기지 않고 문서에 `임시`로 표시한다.
- 변경된 사양은 구현과 테스트보다 먼저 또는 같은 커밋에서 갱신한다.
