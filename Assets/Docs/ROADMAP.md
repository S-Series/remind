2026-09-30 기준 A1의 변경 분류·이동 GUID 조사는 일부 완료했다. 구체적 수치와
경로 불일치, 기존 XML의 출처는 [TASKS.md](TASKS.md)에 기록한다. A1 전체와 A2/A3를
완료로 표시하지 않는다. 동일한 대상 파일의 검증 산출물이 있으면 재사용하고,
변경 영향이나 증거 누락이 있는 범위만 다시 확인한다.
같은 날 A1의 미리보기 경로와 fixture 역할, 원본/격리 복사본 해시 대조를 진행했다.
Unity Editor 라이선스 부재로 EditMode·PlayMode·제품 빌드는 실행 전 종료되어
A2/A3 완료 조건은 여전히 충족하지 못했다. 실행 기록은 TASKS의 통합 기준선 항목과
`Logs/IntegrationBaseline/20260930-0948/report.md`에 둔다.
이후 승인된 격리 실행에서 1,562개 파일 고정본의 EditMode 114/114,
두 곡 smoke, Play/Chart Windows 빌드와 상대 제품 DLL 제외를 확인했다.
Unity Editor Search 시작 예외와 느린 로드·실패/중단·수동 입력 검수는 남는다.
이후 추가된 능력·정산 파일은 이 결과에 포함되지 않는다. 실행 근거는
`Logs/IntegrationBaseline/20260930-A2A3/report.md`에 보존했다.

이미 복구한 4개 테스트를 다시 만드는 작업은 없다. 최신 코드에서 재현되는 실패만
원인별로 처리하며, 과거 통과 기록을 새 변경 전체의 통과로 승계하지 않는다.
`BootstrapLoadingController`의 현재 백분율은 최소 표시 시간의 진행률이다.
실제 리소스 로딩 진행률이 필요한지는 D1에서 결정한다.

#### D1에서 결정할 캐릭터 능력·정산 정책

아래는 제품 연결 전 결정할 항목이며 아직 제품 정책으로 확정하지 않았다.
이전 Hard·보상 +20%·월드 진행 +30%는 설명용 수치였다. 현재 승인된 개발 예시는
Hard 게이지·월드 진행 +20%·보상 +50%다. 개발용 Hard 규칙 자산과 시작 세션
연결은 검증했지만 최종 밸런스나 실제 지급 정책을 확정한 것은 아니다.

| 정책 | 결정할 내용 |
| --- | --- |
| 능력 중첩 | 합산/곱산, 적용 순서·상한, 캐릭터 조합 조건 |
| 게이지 충돌 | 캐릭터·모드·콘텐츠 요구의 우선순위, 선택할 전체 게이지 규칙 |
| 최대·초기 체력 | 최대 HP 증가 시 초기 HP·클리어 기준도 바꾸는지와 보정 순서 |
| 종료 자격 | 완주·클리어·실패·중도 포기·Auto Play별 보상/월드 진행 인정 조건 |
| 발동 기준 | 조건·통계·표시가 원판정/능력 적용 후 최종 판정 중 무엇을 사용하는지, 방어가 점수·콤보·체력에 미치는 범위 |
| 시간·만료 | 일시정지 중 흐르지 않는 곡/채보 시간 좌표, 만료 시각 포함 여부, 동일 시각 Effect·능력 만료·입력·자동 판정 순서 |
| 재시도·재개 | 재시도 때 횟수·쿨다운 초기화와 시작 조건 재선택 여부, Pause/Resume 시 조건·상태 유지 범위 |
| 정산·월드 | 배수 계산의 반올림/절삭·상한, 시작 시 고정한 월드 대상, 완료 지점 초과 진행량 처리, 중복 정산 식별·저장 실패/재실행 복구 |

#### D2의 능력·정산 작업 분할

캐릭터 보유·장착, 월드와 영구 진행은 Game 책임이다. 두 제품이 동일하게 해석해야 하는
순수 규칙만 Shared 후보로 검토한다. 현재 `GameRule`/`IRuleModifier`는 Game assembly에
있으므로 ChartMaker가 직접 참조하거나 전체 캐릭터 시스템을 Shared로 옮기지 않는다.
`EffectRunner`는 채보 시간표의 연출·기믹 책임을 유지한다.

| ID | 작업 및 책임 범위 | 선행 조건 | 완료 기준 |
| --- | --- | --- | --- |
| D2a | 장착 구성·곡·월드·모드를 시작 조건으로 고정하고 해당 세션의 능력과 전체 게이지 규칙을 선택한다. 최대/초기 HP, 판정별 증감, 클리어 기준, 즉시 실패·실패 후 계속 여부를 함께 구성한다. | D1 해당 정책, A3; 통합은 B 완료 후 | 플레이 중 장착/월드 변경이 진행 중 세션을 바꾸지 않는다. 게이지 enum만 바꾸지 않으며 최대 HP modifier와 초기 HP 정책을 구분해 검증한다. |

현재 `GetInitialHealth`는 기본 초기 HP를 최대 HP 범위로 제한하며, 최대 HP를 올려도
초기 HP를 자동으로 늘리지 않는다. `IRuleModifier` 조회 안에서 횟수를 소비하는 방식은
후보 탐색·실패 조건 재조회로 중복 발동할 수 있다. Long Scratch Mid/End의 별도 판정과
공용 세션이 직접 만드는 자동 Miss까지 D2b의 확정 경계에 포함해 조사한다.
관련 사건에서 활성 능력을 평가하고, 시작에 결정 가능한 조건은 한 번 계산한다.
2026-09-30에는 Game 전용 신규 파일로 네 능력 종류 중 월드 진행·보상 두 종류의
예시 시작 snapshot과 순수 decimal 정산량 계산을 구현했다. 별도 고정본의 Unity
EditMode 122/122가 통과했다. 이후 개발용 Hard 전체 게이지 규칙, 선택 API,
세션별 규칙 복사/시도 snapshot, 실패한 시작의 롤백, Result 전달과 Auto Play
사용 이력의 기록 제외를 연결했다. 최신 격리본에서 EditMode 130/130,
기존 두 곡 Normal 및 Hard PlayMode smoke와 Game Windows 빌드를 확인했다.
검증 범위는 `Logs/IntegrationBaseline/20260930-D2a-r4/report.md`에 둔다.
정식 캐릭터 장착 UI·월드 대상, 조건부 능력 발동, 종료 자격·반올림·실제 지급·
중복 방지·저장 이행과 최종 Hard 밸런스는 미연결/미확정이며 D2 전체 완료로
계산하지 않는다.

#### 연속 도전·히든곡·선택형 제약의 결정과 구현 순서

이 기능은 현재 구현 완료로 계산하지 않는다. D1에서 첫 출시 포함 여부와
[ARCHITECTURE.md](ARCHITECTURE.md)의 미결정 정책을 확정한다. 포함한다면 D2에서
Game 전용 도전 진행자, 분기 수용·다음 곡 준비, 종료 사유, 제약 합성, 기록·해금
저장 계약을 한 경로로 구현한다. D3에서 실제 곡 조건·제약 데이터·표시 콘텐츠를
제작한다. 첫 수용 경로는 A곡 조건 달성 → B곡 전환 → B곡 성공 → 해금 저장이다.
조건 미달, 같은 시각 마지막 판정, 대상 준비 실패, 중단·재시도, 제약 충돌과 저장
복구를 회귀 대상으로 둔다. 전환 끊김과 자산 준비 비용은 E2에서 측정한다.

deadline 캐시는 동적 판정 창과 같은 시각의 상태 변경을 보존하는 계약이 있어야 적용한다.

### F. 출시 후보 승인

B/C의 해당 수용 항목, D의 출시 필수 기능·콘텐츠, E의 품질 기준을 통과한 뒤 두 제품을
같은 원본 기준에서 빌드한다. 남은 결함, 지원 환경, 수동 검수 기록과 알려진 제한을 함께
남긴다. 출시 범위에서 미룬 기능은 후속 작업으로 보존한다. commit/push/배포는 자동 수행하지 않는다.

## 작업 배분과 통합 순서

당장 수행할 작업은 다음 순서로 좁힌다. 담당은 책임 구분이며 별도 채팅/에이전트를
이미 생성하거나 실행했다는 의미가 아니다.

| 순서 | 작업 | 책임 | 검토 가능한 산출물 |
| --- | --- | --- | --- |
| 1 | A1: 미리보기 경로·에셋 이동·fixture 정리와 검사 대상 고정 | 통합/콘텐츠 경계 | 이동·삭제/대체 목록, 경로 수정 diff, 대상 파일/해시 및 검사 출처 |
| 2 | A2: 최신 자동 회귀와 실패 원인별 수정 | Game 통합 + Shared/ChartMaker 해당 영역 | EditMode XML, 두 곡 smoke 로그, 결함별 수정과 재검사 결과 |
| 3 | A3: Game/ChartMaker 독립 빌드 | 제품 구성 | 두 실행 파일, 씬/define/DLL 경계 결과, 동일 원본 근거 |
| 1~3과 병행 | D1: 출시 범위와 검수 환경 결정 | 사용자 기획 + 기술 정리 | 필수/후속 기능표, Test Play 요구, 지원 환경·수용 기준 |

- A를 먼저 진행하며 D1의 범위 결정은 병행할 수 있다. A3 뒤에는 B와 C의 검수 준비,
  E2의 초기 측정을 나눌 수 있다. 수동 검수 대기 중에는 독립된 문서·자동 검사 작업을 진행한다.
- Game 흐름/설정 작업은 `AppRoot`, 씬 전환, Home/Settings/Bootstrap을 한 묶음으로 둔다.
  ChartMaker 작업은 편집·파일·Preview를 맡는다. 공용 계약 변경은 먼저 합의한 뒤 양쪽에 반영한다.
- `REmindBaselineChecks.cs`, `PlayableGameSmokeRunner.cs`, 공용 모델, 카탈로그/빌드 설정,
  같은 씬·프리팹은 여러 작업이 동시에 수정하지 않도록 한 통합 담당자를 둔다.
- 능력 D2와 탐색 최적화 E2b는 `PlayableJudgementSession`, `NoteJudgementSystem`,
  `GameplaySessionState` 등 같은 판정 파일을 동시에 수정하지 않는다. E2a 초기 계측·회귀
  설계는 병행할 수 있다. D1 정책/계약→D2a 시작 고정→D2b 판정 확정 경계→D2c/D2d
  캐릭터 한 명의 정산까지 통합·회귀한 뒤 기준선을 갱신하고 E2b→E2c로 인계한다.
- 각 작업은 ID, 입력 계약, 수정 파일 범위, 선행 조건, 검증 명령·산출물, 남은 수동 검수를
  인수인계한다. 실행 담당자는 착수 때 지정하며 이 문서만으로 별도 작업을 자동 시작하지 않는다.
- 구조 개선·화면 연출·기능 추가는 검토 가능한 크기로 분리한다. 변경 후에는 영향을 받은
  경계의 검사와 문서를 갱신한다.

## Phase 정의

### Phase 1. ChartMaker 안정화
편집·저장·복구·Undo/Redo와 실제 제작 흐름을 안정화한다.

### Phase 2. Shared Chart / Runtime Core 정리
Chart format, validation, timing/position, Runtime package의 Source of Truth를 정리한다.

### Phase 3. Actual Gameplay Runtime 재구축
최종 Game scene/composition root가 Shared Runtime package를 직접 소비하게 한다.

### Phase 4. Input / Judgement / GameRule 완성
현행 Long/Scratch를 보존하며 실제 입력, 판정, 규칙과 세션 상태를 완성한다.

### Phase 5. Effect / MusicGimmick 완성
공용 실행 계약과 곡별 등록, 실제 콘텐츠용 capability 및 오류 정책을 완성한다.

### Phase 6. Presentation / Camera / UI
Game과 ChartMaker가 공용 계산을 소비하되 각자의 표시/UI를 독립 구현한다.

### Phase 7. Score / Result / Gameplay Flow
곡 선택부터 플레이, 결과, 다음 화면까지 Player 흐름을 연결한다.

### Phase 8. Build Separation / Content Pipeline
Game/ChartMaker assembly·Build Profile과 검증된 콘텐츠 배포 경계를 확립한다.

### Phase 9. Final Content / Polish / Release Readiness
실제 곡/채보, 성능, 호환성, 접근성, 배포 전 회귀를 마무리한다.
